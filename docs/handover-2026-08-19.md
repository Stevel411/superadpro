## 3. Data-integrity fixes (two real ones)

### 3a. Orphaned active campaigns not rolling into pack progress — `0fbfd98c1`, `9b428c667`
Root cause: active campaigns with `pack_purchase_id = NULL` (not linked to any pack) deliver views that roll into **no** pack's aggregate — invisible on Pack-progress, which only renders linked packs. On Steve's own account, campaign 1 ("Is BitCoin Still Worth Buying?", 85 views) was attached to nothing; the $1000 pack showed only the other 13 (of 98 total). New endpoint **`/admin/api/al/link-orphan-campaigns`** (dry-run default, `?apply=1`, `?user_id=N` / `?sweep=1`) attaches active orphans to the owner's highest pack with a free slot, same slot rules as draft activation. Ran on user 1 → $1000 pack now reads 98/120,000 · 2 videos.
**Gotcha:** `pack_purchase_id` lives on the `video_campaigns` table but **NOT on the `VideoCampaign` ORM model** (added via startup `ALTER`, raw-SQL-only). ORM filters on it throw — use raw SQL (first version 500'd on exactly this).

### 3b. `resolve-dispute` control-flow bug — `2767ed0c9`
The success `return` sat **inside the `except` block**, so a **confirm** would run `_als.confirm()` (minting PackPurchase + commission) and then fall through to `intent.status = "cancelled"` — money moved but the intent read cancelled. Also the momentum-feed "sale" posted on cancel. Surfaced while investigating aron's pending intent. Now: confirm posts + returns cleanly; cancel voids with no pack/commission/feed post. The normal payee-confirm path was never affected (that's why it hadn't bitten — the 3 confirmed settlements went through that path, not this one).

## 7. Key learnings (added to LAUNCH_LOG)
1. **oEmbed is the video embeddability gate** — verify every third-party video before seeding (404 removed / 401 embed-disabled / 200 OK).
2. **`pack_purchase_id` is raw-SQL-only** on `video_campaigns` — not on the `VideoCampaign` ORM model. Query/update it via raw SQL, never ORM attributes.
3. **Admin owns every tier via the `_ADMIN_LEVEL` sentinel** (`al_engine.owned_level`), which is virtual — it does NOT create `PackPurchase` rows. Any panel that reads real rows must special-case `is_admin` if it should reflect all-ownership.
4. **`resolve-dispute` pattern** — the confirm/cancel branches were entangled by a mis-indented return; when touching dispute code, keep confirm (posts + returns) and cancel (voids, no side effects) strictly separate.
5. Campaigns attach to the **highest pack with a free slot** — a member with many packs but few videos will show most packs empty; that's correct, not a bug.
